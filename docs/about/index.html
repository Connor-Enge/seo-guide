About The Guide to SEO — Who Writes It & How

Maintained by Connor Enge · Updated 2026-08-05

This is a hand-built guide to search engine optimization, written and maintained by Connor Enge. Its aim is narrow and honest: explain how search actually works and how to earn rankings with genuinely useful pages — no secret tricks, no padding, no recycled listicles.

Google's own guidance on helpful, people-first content says readers should be able to find "background about the author or the site that publishes it." This page is that background — who writes this, how it is researched, and how it stays current — so you can judge whether to trust it.

Who writes this

Every page here is written and maintained by Connor Enge, a developer who builds for the open web and cares about sites that are fast, accessible, and worth reading. Rather than ask you to take a résumé on faith, this project shows its work: the site itself is the credential. It is a hand-written static generator — no JavaScript, no tracking, a tiny stylesheet — that ships semantic HTML, one <h1> per page, canonical URLs, Open Graph and Twitter cards, and valid Article, BreadcrumbList, and FAQPage structured data. It practices the technical SEO it teaches, and passes Core Web Vitals almost by construction. What you read here is what the author actually does.

You can reach the author or see the code behind this site on GitHub (Connor-Enge).

How each page is researched

The value of an SEO guide is only as good as its sources, so this one is deliberate about them:

  • Primary sources first. Guidance is drawn from Google Search Central and web.dev, with web standards from the W3C and MDN. Where a claim traces to Google or a standards body, it is stated as such.
  • No scaled or auto-generated filler. Google's scaled content abuse policy exists because the web is drowning in thin, mass-produced pages. This guide is written one page at a time, by a person, to be read by a person.
  • Value over volume. A page ships when it says something complete and correct — not to hit a word count or a publishing quota.
  • Honest about uncertainty. SEO involves systems Google does not fully document. Where something is a well-founded practice rather than a confirmed rule, the text says so instead of pretending to certainty.

How often it is updated

Search changes, so pages here are revised rather than left to rot. Every guide page and blog post carries a visible "Updated" date, and that date reflects a real review against current primary sources — not a cosmetic bump. When Google ships a change that affects the advice (a new Core Web Vitals threshold, a policy update, a deprecated feature), the affected pages are corrected and re-dated.

Corrections

Accuracy matters more than being right the first time. If you spot something out of date, unclear, or simply wrong, corrections are welcome and fixed promptly — a dated correction is a feature of a trustworthy source, not an embarrassment. The commitment here is simple: fix errors quickly, and be transparent about when a page changed.

Editorial principles

Everything on this site is held to the same short standard:

  1. People-first. Written to help a reader accomplish something, not to manipulate a ranking.
  2. Sourced. Traceable to primary documentation, not to the last blog that repeated it.
  3. Original. It adds analysis and worked examples, not a rewrite of someone else's post.
  4. Fast and accessible. The medium is the message: a lean, semantic, keyboard-navigable site.
  5. Current. Reviewed against the sources and dated, so you know how fresh the advice is.

If a page here ever fails one of these, it is a bug — please flag it.
